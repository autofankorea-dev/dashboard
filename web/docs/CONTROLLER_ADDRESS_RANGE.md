# 컨트롤러 명령 번호 범위

현재 명령 대상 `eqpmn_no`는 **01~48**이다. 모듈당 최대 48대라는 운영 범위에 맞춰 대시보드와 EC2를 함께 적용한다. 기존 문서의 1~10 제한은 11~14번 등 수신 가능한 컨트롤러의 명령을 거절하므로 현재 downlink에 적용하지 않는다.

- 대시보드: `lib/domain/controller-key.ts`의 `parseCommandEqpmnNo`가 단건·일괄·통합 채널·장비 설정 액션과 0x0C/0x0D/0x0E 인코더의 공통 검증이다.
- EC2: `controller_identity.py`의 `EQPMN_NO_MIN=1`, `EQPMN_NO_MAX=48`을 패킷 생성기가 사용한다.
- 0, 49 이상과 잘못된 문자열은 명령으로 보내지 않는다. 화면 표시용 `normalizeEqpmnNo`의 레거시 1~99 호환은 유지하며 명령 검증으로 사용하지 않는다.
- 번호는 기존 패킷 byte 4의 uint8에 그대로 담긴다. 패킷 길이·CRC·채널 마스크·MQTT 토픽은 바뀌지 않는다. DB migration은 필요하지 않다.

검증은 01~48 전체 주소, 11~14번 일괄 DB 등록, 경계 밖 주소 거절, EC2와의 패킷/CRC 비교로 수행한다. 검증 중 운영 MQTT 명령은 발행하지 않는다.

배포 시 EC2 파일은 백업 후 기존 로컬 변경을 유지한 채 상한만 바꾼다. 대기·전송 중 명령이 없는 시점에 C와 RS 프로세스를 재시작한다. RS의 ACK용 uplink 해석도 같은 상수를 import하므로 함께 갱신해야 한다. 브로커는 재시작하지 않는다. 대시보드 변경을 Git 배포한다. ACK timeout과 성공/실패 집계는 별도 변경이다.
