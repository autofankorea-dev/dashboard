# 일괄 적용 집계 단위

모든 일괄 결과·진행 수치는 **컨트롤러 대수**로 표시한다. 채널 A/B/C 수와 DB 명령 행 수를 대수에 더하지 않는다. 같은 컨트롤러 번호라도 농장·모듈이 다르면 다른 대상이다(기존 reading key 사용).

- 접수 결과: `sent`는 요청한 설정이 모두 DB에 접수된 컨트롤러 수다. 장비 반영 확인을 뜻하지 않는다.
- 실패: 여러 채널의 등록 실패나 DB 실패가 있어도 해당 컨트롤러는 실패 1대다. 일부 채널이 등록됐어도 실패가 있으면 접수 성공 수에서 제외한다. 등록된 명령 ID는 상태 추적을 위해 보존한다.
- 진행: 한 컨트롤러에 여러 명령이 있으면 실패/취소가 하나라도 있으면 실패, 나머지는 접수 대기 → 전송 → 전체 applied 확인 순으로 분류한다. 단계는 상호 배타적이다.
- DB 행을 만들지 못한 등록 실패 대상도 이번 요청의 전체 대상과 실패 수에 포함한다.
- 새 요청은 이전 요청 이력과 섞지 않으며 16행으로 잘라내지 않는다. 채널별 상세 표시와 실제 명령 전송 방식은 유지한다.

예: 14대에서 각 두 채널을 요청해 4대가 거절되면 **접수 10대 + 실패 4대 = 대상 14대**다. 실패 8건으로 표시하지 않는다. 진행 중에도 **접수 + 전송 + 확인 + 실패 = 이번 요청 대상 대수**를 유지한다. 오프라인·채널 미매칭으로 전송 대상에서 제외된 대수는 별도로 표시한다.

회귀 검증: 채널 중복 실패, 일부 채널만 등록된 경우, DB 등록 실패, 전체 거절, 서로 다른 농장의 동일 번호, 48대 진행 집계. 운영 DB 삽입이나 MQTT 전송 없이 모의 DB와 순수 집계로 검증한다.
